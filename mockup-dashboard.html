Schedule rules & compliance

The system enforces these automatically. Conflicts surface inline as you build the schedule.

Availability options

Allow drivers to manage their own availability
When ON, drivers see and edit availability in their app (subject to rules below). When OFF, only you set each driver's availability — drivers see their schedule but can't change what days they work.

Driver-managed mode is ON. Rules below apply to what drivers can declare in their app.

Operating days
Drivers can only declare availability for days you operate. Off days are hidden from the driver app.
Required days · all drivers must be available
Drivers cannot mark these days unavailable. Use sparingly — typically high-volume days.
Minimum days available per driver
Drivers must declare at least this many days as available (across operating days).
Maximum days unavailable per driver
Drivers can't mark more than this many operating days as unavailable.
Hours-per-week range allowed
Drivers can set their min/max hours within this range only.
to
Allow drivers to set "preferred" days
If off, drivers can only mark days as available or unavailable — no preference distinction.
Allow drivers to opt into backup pool
If off, you assign backup status manually. If on, drivers self-select.
Allow drivers to opt into swap marketplace
If off, drivers can't post or claim swaps — manager only.
Availability changes require owner approval
Driver edits stay pending until you approve. Useful for tighter control.
Availability change cutoff
Drivers cannot change availability within this many days of an unpublished week.

Hours & rest

Max hours per week per driver
Warns when a driver's scheduled hours exceed this limit.
Max consecutive working days
Drivers can't be scheduled more than this many days in a row.
Min rest between shifts (hours)
DOT-style rest enforcement.
Required days off per month
Auto-block manager from scheduling beyond.
